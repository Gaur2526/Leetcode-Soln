# 3876. Construct Uniform Parity Array II

Date solved: 2026-09-03  Status: ✅ Accepted

## Problem

    ```
    You are given an array nums1 of n distinct integers. You want to construct another array nums2 of length n such that the elements in nums2 are either all odd or all even. For each index i, you must choose exactly one of the following:

    nums2[i] = nums1[i]

    nums2[i] = nums1[i] - nums1[j], for an index j != i, such that nums1[i] - nums1[j] >= 1.

    Return true if it is possible to construct such an array, otherwise return false.
    ```

## Examples

    ```
    Example 1

        Input

        nums1 = [1,4,7]

        Output

        true

        Explanation

        Choose nums2[0] = nums1[0] = 1.

        Choose nums2[1] = nums1[1] - nums1[0] = 4 - 1 = 3.

        Choose nums2[2] = nums1[2] = 7.

        nums2 = [1, 3, 7], and all elements are odd. Thus, the answer is true.

    Example 2

        Input

        nums1 = [2,3]

        Output

        false

        Explanation

        The even element 2 cannot be changed into an odd positive number because the only odd element 3 is larger than it.

        The odd element 3 can stay odd, but there is no valid way to make 2 odd.

        Thus, it is impossible to construct a uniform parity array.

    Example 3

        Input

        nums1 = [4,6]

        Output

        true

        Explanation

        Choose nums2[0] = nums1[0] = 4.

        Choose nums2[1] = nums1[1] = 6.

        nums2 = [4, 6], and all elements are even. Thus, the answer is true.
    ```

## Constraints

    ```
    1 <= n == nums1.length <= 105

    1 <= nums1[i] <= 109

    nums1 consists of distinct integers.
    ```

## Approach

    ```
    The important observation is that only parity matters.

    For two numbers a and b:

        a - b is odd  if a and b have different parity.

        a - b is even if a and b have the same parity.

    Case 1: All elements are already odd.

        We can keep every element unchanged.

        Therefore, the answer is true.

    Case 2: All elements are already even.

        We can keep every element unchanged.

        Therefore, the answer is true.

    Case 3: The array contains both odd and even elements.

        We cannot make the smallest odd element even because there is no smaller odd
        element that it can subtract.

        Therefore, the final array must be all odd.

        Every even element needs to subtract an odd element smaller than itself.

        So, if minOdd is the smallest odd element and minEven is the smallest even
        element, the construction is possible exactly when:

            minOdd < minEven

        If minOdd < minEven, use minOdd as the subtracted value for every even
        element. Since even - odd = odd, every element becomes odd.

        If minOdd > minEven, the smallest even element has no smaller odd element
        to subtract, so the construction is impossible.
    ```

## Complexity

    ```
    Time: O(n)

    Space: O(1)
    ```

## Solution

    ```
    class Solution {

    public:

        bool uniformArray(vector<int>& nums1) {

            int minOdd = INT_MAX;
            int minEven = INT_MAX;

            for (int x : nums1) {

                if (x & 1)
                    minOdd = min(minOdd, x);
                else
                    minEven = min(minEven, x);
            }

            // All elements are odd
            if (minEven == INT_MAX)
                return true;

            // All elements are even
            if (minOdd == INT_MAX)
                return true;

            // Mixed parity: make everything odd
            return minOdd < minEven;
        }
    };
    ```

## Notes

    ```
    Key insight:

        The parity of a - b depends only on the parity of a and b.

        odd - odd   = even
        even - even = even
        odd - even  = odd
        even - odd  = odd

    In a mixed-parity array, the smallest odd element is the key.

    If the smallest odd element is smaller than the smallest even element,
    it can be subtracted from every even element to turn all of them odd.

    The smallest odd element itself cannot become even because there is no
    smaller odd element available.

    Therefore:

        all odd  -> true
        all even -> true
        mixed    -> minOdd < minEven
    ```

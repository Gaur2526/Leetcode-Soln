# 1096. Brace Expansion II

Date Solved: September 25, 2026
Status: Solved

## Problem Statement

Given an expression containing lowercase letters, braces {}, and commas, return all distinct words represented by the expression in sorted order.

The grammar has three main rules:

 A lowercase letter represents a set containing that single letter.
 Comma-separated expressions represent the union of their possible words.
 Concatenated expressions represent all possible concatenations between their words.

For example:

{a,b} represents:

{"a", "b"}

And:

{a,b}{c,d}

represents:

{"ac", "ad", "bc", "bd"}

---

## Examples

### Example 1

Input:

expression = "{a,b}{c,{d,e}}"

Output:

["ac","ad","ae","bc","bd","be"]

### Example 2

Input:

expression = "{{a,z},a{b,c},{ab,z}}"

Output:

["a","ab","ac","z"]

Explanation:

All possible words are generated and duplicates are automatically removed.

---

## Constraints

 1 <= expression.length <= 60
 expression[i] consists of '{', '}', ',' or lowercase English letters.
 The expression represents a valid set of words.

---

# Approach

We use recursive descent parsing.

The main idea is to convert every part of the expression into a:

set<string>

Using a set automatically removes duplicate words and keeps the final result sorted.

There are two important operations:

 Union
 Concatenation

### Step 1: Parse Letters

If the current character is a lowercase letter, it represents a set containing only that letter.

For example:

a -> {"a"}

### Step 2: Parse Braces

When we encounter {, we recursively parse the expressions inside it.

For example:

{a,b,c}

is parsed as:

{"a"} ∪ {"b"} ∪ {"c"}

The results are inserted into the same set.

### Step 3: Handle Union

When a comma is encountered, the expression before the comma and the expression after it are separate alternatives.

For example:

{a,b}

becomes:

{"a"} ∪ {"b"}

We insert all words from both sets into one set.

### Step 4: Handle Concatenation

When two expressions appear next to each other, their results need to be concatenated.

For example:

{a,b}{c,d}

First set:

{"a", "b"}

Second set:

{"c", "d"}

We generate:

ac, ad, bc, bd

This is a Cartesian product of the two sets.

### Step 5: Recursive Parsing

The parser continues until it reaches:

 } → end of the current brace expression.
 , → end of the current union expression.

After parsing everything, the final set is converted into a vector.

Because set<string> is ordered, the result is already lexicographically sorted.

---

# Complexity

Let W be the number of distinct generated words and L be their maximum length.

The dominant cost comes from generating and storing the actual words.

### Time Complexity

Approximately:

O(W * L)

plus the cost of set operations and intermediate concatenations.

### Space Complexity

Approximately:

O(W * L)

for storing the generated words.

# Solution

cpp
class Solution {
public:
    string s;
    int i = 0;

    set<string> combine(const set<string>& a, const set<string>& b) {
        set<string> res;

        for (const string& x : a) {
            for (const string& y : b) {
                res.insert(x + y);
            }
        }

        return res;
    }

    set<string> parse() {
        set<string> res;

        while (i < s.size() && s[i] != '}' && s[i] != ',') {
            set<string> cur;

            if (s[i] == '{') {
                i++; // skip '{'

                cur = parse();

                while (s[i] == ',') {
                    i++; // skip ','

                    set<string> next = parse();

                    cur.insert(next.begin(), next.end());
                }

                i++; // skip '}'
            } else {
                cur.insert(string(1, s[i]));
                i++;
            }

            if (res.empty()) {
                res = cur;
            } else {
                res = combine(res, cur);
            }
        }

        return res;
    }

    vector<string> braceExpansionII(string expression) {
        s = expression;
        i = 0;

        set<string> result = parse();

        return vector<string>(result.begin(), result.end());
    }
};

# Dry Run

Consider:

expression = "{a,b}{c,{d,e}}"

### First Part

Parse:

{a,b}

This gives:

{"a", "b"}

### Second Part

Parse:

{c,{d,e}}

The inner expression:

{d,e}

gives:

{"d", "e"}

Combining with c:

{"c", "d", "e"}

### Concatenate Both Parts

First set:

{"a", "b"}

Second set:

{"c", "d", "e"}

Generate:

 a + c = ac
 a + d = ad
 a + e = ae
 b + c = bc
 b + d = bd
 b + e = be

Final result:

["ac","ad","ae","bc","bd","be"]

---

# Key Insight

Every expression can be represented as a set of strings.

Then:

 Comma means union.
 Adjacent expressions mean concatenation.
 Braces control the grouping of these operations.

Using set<string> is especially useful because it automatically removes duplicates and keeps the final result sorted.

---

# Notes

 Use recursive descent parsing to handle nested braces.
 Use set<string> to automatically remove duplicates.
 Union is implemented by inserting elements from one set into another.
 Concatenation is implemented using a Cartesian product.
 The parser stops at } or , depending on the current context.
 The final set<string> is already sorted lexicographically.

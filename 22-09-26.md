# 3525. Find X Value of Array II

Date Solved: September 22, 2026
Status: Solved

## Problem Statement

You are given an array of positive integers nums, a positive integer k, and a list of queries.

Each query is:

[index, value, start, x]

For every query:

 Update nums[index] to value. This update persists for future queries.
 Remove the prefix nums[0..start-1].
 From the remaining array nums[start..n-1], remove any suffix.
 The remaining array must be non-empty.
 Count how many possible remaining arrays have a product whose remainder modulo k is x.

Return the answer for every query.

---

## Examples

### Example 1

Input:
nums = [1,2,3,4,5]
k = 3
queries = [[2,2,0,2],[3,3,3,0],[0,1,0,1]]

Output:
[2,2,2]

### Example 2

Input:
nums = [1,2,4,8,16,32]
k = 4
queries = [[0,2,0,2],[0,2,0,1]]

Output:
[1,0]

### Example 3

Input:
nums = [1,1,2,1,1]
k = 2
queries = [[2,1,0,1]]

Output:
[5]

---

## Constraints

 1 <= nums[i] <= 10^9
 1 <= nums.length <= 10^5
 1 <= k <= 5
 1 <= queries.length <= 2 * 10^4
 0 <= index <= nums.length - 1
 1 <= value <= 10^9
 0 <= start <= nums.length - 1
 0 <= x <= k - 1

---

# Approach

The previous solution used a Segment Tree with dynamically allocated vector<int> inside every node.

Since k <= 5, we can optimize this significantly by using a fixed-size array of size 5.

We also use an iterative Segment Tree instead of a recursive one.

After removing the prefix nums[0..start-1], every possible remaining array is a non-empty prefix of:

nums[start..n-1]

Therefore, for every segment we need to know the number of prefixes for every possible product remainder.

### Step 1: Store Information in Each Node

Each node stores two things:

 prod → product of the entire segment modulo k.
 pref[r] → number of non-empty prefixes whose product has remainder r.

Because k <= 5, we only need:

pref[0..4]

### Step 2: Leaf Node

For a single value value:

r = value % k

The complete product is:

prod = r

There is exactly one non-empty prefix, so:

pref[r] = 1

### Step 3: Merge Two Nodes

Suppose a segment is:

Left + Right

There are two types of prefixes.

Type 1: Prefix lies completely inside Left

These prefixes remain unchanged.

Therefore:

res.pref[r] += left.pref[r]

Type 2: Prefix contains all of Left and a prefix of Right

Suppose a prefix of Right has remainder r.

The combined product is:

(left.prod * r) % k

Therefore:

res.pref[newR] += right.pref[r]

where:

newR = (left.prod * r) % k

The complete product of the combined segment is:

res.prod = (left.prod * right.prod) % k

### Step 4: Point Update

For every query, first update:

nums[index] = value

We update the corresponding leaf and then recalculate its ancestors.

Because the Segment Tree is iterative, this avoids recursive function overhead.

### Step 5: Range Query

We query:

[start, n - 1]

The resulting node contains the number of non-empty prefixes for every possible remainder.

Therefore, the answer is:

result.pref[x]

### Step 6: Why This Version Is Faster

The important optimization is avoiding dynamic memory allocation.

Instead of:

vector<int> pref

we use:

int pref[5]

This removes repeated vector allocations and copies during Segment Tree merges.

We also use an iterative Segment Tree, which reduces function-call overhead during updates and queries.

---

# Complexity

### Time Complexity

Build:

O(n * k)

Each Update:

O(k log n)

Each Query:

O(k log n)

Since:

k <= 5

this is effectively:

O(log n)

per update/query.

### Space Complexity

O(n * k)

The Segment Tree stores k prefix counts for every node.

# Solution

cpp
class Solution {
public:
    struct Node {
        int prod;
        int pref[5];

        Node() {
            prod = 1;
            memset(pref, 0, sizeof(pref));
        }
    };

    int k;
    vector<Node> tree;

    Node merge(const Node& a, const Node& b) {
        Node res;

        res.prod = (a.prod * b.prod) % k;

        for (int r = 0; r < k; r++) {
            res.pref[r] = a.pref[r];
        }

        for (int r = 0; r < k; r++) {
            int nr = (a.prod * r) % k;
            res.pref[nr] += b.pref[r];
        }

        return res;
    }

    Node makeNode(int value) {
        Node res;

        int r = value % k;

        res.prod = r;
        res.pref[r] = 1;

        return res;
    }

    void update(int pos, int value, int size) {
        pos += size;
        tree[pos] = makeNode(value);

        for (pos >>= 1; pos > 0; pos >>= 1) {
            tree[pos] = merge(tree[pos << 1], tree[pos << 1 | 1]);
        }
    }

    Node query(int l, int r, int size) {
        Node leftResult;
        Node rightResult;

        l += size;
        r += size;

        while (l <= r) {
            if (l & 1) {
                leftResult = merge(leftResult, tree[l++]);
            }

            if (!(r & 1)) {
                rightResult = merge(tree[r--], rightResult);
            }

            l >>= 1;
            r >>= 1;
        }

        return merge(leftResult, rightResult);
    }

    vector<int> resultArray(vector<int>& nums, int k,
                            vector<vector<int>>& queries) {
        this->k = k;

        int n = nums.size();
        int size = 1;

        while (size < n) {
            size <<= 1;
        }

        tree.resize(2 * size);

        for (int i = 0; i < n; i++) {
            tree[size + i] = makeNode(nums[i]);
        }

        for (int i = size - 1; i >= 1; i--) {
            tree[i] = merge(tree[i << 1], tree[i << 1 | 1]);
        }

        vector<int> ans;
        ans.reserve(queries.size());

        for (auto& q : queries) {
            int index = q[0];
            int value = q[1];
            int start = q[2];
            int x = q[3];

            update(index, value, size);

            Node res = query(start, n - 1, size);

            ans.push_back(res.pref[x]);
        }

        return ans;
    }
};

# Dry Run

Consider:

nums = [1, 2, 3]

k = 3

Query:

start = 0, x = 2

The possible non-empty prefixes are:

 [1] → product 1 → remainder 1
 [1,2] → product 2 → remainder 2
 [1,2,3] → product 6 → remainder 0

Therefore:

pref[0] = 1

pref[1] = 1

pref[2] = 1

Since the query asks for:

x = 2

the answer is:

pref[2] = 1

# Key Insight

The important observation is that after removing the required prefix, removing a suffix leaves exactly one non-empty prefix of the remaining range.

For every segment, we only need:

 The product of the complete segment modulo k.
 The count of prefixes for each possible remainder.

When combining two segments, a prefix either:

 Ends inside the left segment.
 Contains the entire left segment and extends into the right segment.

This allows the Segment Tree to combine the information efficiently.

Because k <= 5, a fixed array of size 5 is enough and avoids the overhead of dynamic vectors.

# Notes

 Use an iterative Segment Tree for lower overhead.
 Use int pref[5] instead of vector<int>.
 Store products modulo k.
 Point updates persist for all future queries.
 Query range is always [start, n - 1].
 Every valid remaining array is a non-empty prefix of this range.
 Boundary and empty-segment handling are naturally supported by the default node.
 The optimization mainly removes dynamic allocation and recursive overhead while keeping the same Segment Tree idea.

# 3414. Maximum Score of Non-overlapping Intervals

**Date Solved:** September 12, 2026
**Status:** Solved

## Problem Statement

You are given a 2D integer array `intervals`, where:

```text
intervals[i] = [li, ri, weighti]
```

Each interval starts at `li`, ends at `ri`, and has a weight `weighti`.

You can choose **at most 4 non-overlapping intervals**.

Two intervals are non-overlapping if they **do not share any point**.

Therefore, if one interval ends at `r`, the next interval must start at a position **strictly greater than `r`**.

Return the **lexicographically smallest array of indices** among all choices having the maximum possible total weight.

---

## Examples

### Example 1

```text
Input:
intervals = [[1,3,2],[4,5,2],[1,5,5],[6,9,3],[6,7,1],[8,9,1]]

Output:
[2,3]
```

The intervals at indices `2` and `3` have weights:

```text
5 + 3 = 8
```

---

### Example 2

```text
Input:
intervals = [[5,8,1],[6,7,7],[4,7,3],[9,10,6],[7,8,2],[11,14,3],[3,5,5]]

Output:
[1,3,5,6]
```

Total weight:

```text
7 + 6 + 3 + 5 = 21
```

---

## Constraints

* `1 <= intervals.length <= 5 * 10^4`
* `intervals[i].length == 3`
* `1 <= li <= ri <= 10^9`
* `1 <= weighti <= 10^9`

---

# Approach

This problem is a variation of **Weighted Interval Scheduling**.

The additional constraints are:

1. We can select at most **4 intervals**.
2. Among all maximum-score solutions, we need the **lexicographically smallest indices**.

We can solve it using:

* Sorting
* Binary Search
* Dynamic Programming

---

## Step 1: Store Original Indices

After sorting the intervals, their positions will change.

Therefore, we store:

```text
{start, end, weight, original_index}
```

For example:

```text
[1, 5, 10]
```

at original index `7` becomes:

```text
{1, 5, 10, 7}
```

This allows us to return the original interval indices.

---

## Step 2: Sort Intervals

Sort all intervals by their start position.

```cpp
sort(a.begin(), a.end());
```

We also store all start positions:

```cpp
vector<long long> starts(n);
```

This allows us to perform binary search.

---

## Step 3: Find the Next Compatible Interval

Suppose the current interval is:

```text
[start, end, weight]
```

The next interval must satisfy:

```text
next.start > end
```

Notice the **strictly greater than**.

This is because intervals sharing an endpoint are considered overlapping.

For example:

```text
[1, 5]
[5, 8]
```

are overlapping.

Therefore, we use:

```cpp
upper_bound(starts.begin(), starts.end(), end)
```

instead of `lower_bound()`.

For every interval `i`, we calculate:

```text
nxt[i] = first interval whose start > a[i].end
```

---

# Step 4: Dynamic Programming

Define:

```text
dp[i][k]
```

as:

> The best result we can obtain using intervals from index `i` onward, when we are allowed to select at most `k` intervals.

Each DP state stores:

```text
{maximum_score, selected_indices}
```

There are two choices.

### Choice 1: Skip the current interval

```cpp
skip = dp[i + 1][k];
```

### Choice 2: Take the current interval

If we take interval `i`, the next available interval is `nxt[i]`.

Therefore:

```cpp
take = dp[nxt[i]][k - 1];
```

Then add the current interval's weight:

```cpp
take.first += a[i][2];
```

and its original index:

```cpp
take.second.push_back(a[i][3]);
```

---

# Step 5: Lexicographical Tie-Breaking

This is the important part.

We first maximize the score.

If two solutions have different scores:

```text
higher score → better solution
```

If their scores are equal:

```text
same score → lexicographically smaller indices
```

So:

```cpp
if (take.first > skip.first ||
    (take.first == skip.first &&
     take.second < skip.second))
```

chooses the correct result.

---

## Why Do We Sort the Selected Indices?

The DP processes intervals according to their **start positions**, not their original indices.

Therefore, the selected indices might initially look like:

```text
[5, 1, 3]
```

But the answer must be compared as an array of original indices:

```text
[1, 3, 5]
```

So whenever we add an index, we keep the vector sorted:

```cpp
take.second.push_back(a[i][3]);
sort(take.second.begin(), take.second.end());
```

Since we can select at most **4 intervals**, sorting this vector is constant-time in practice.

This ensures that:

```cpp
take.second < skip.second
```

correctly performs the required lexicographical comparison.

---

# Complexity

Let `n` be the number of intervals.

### Sorting

```text
O(n log n)
```

### Binary Search

For every interval, we perform one binary search:

```text
O(n log n)
```

### DP

There are only `4n` states:

```text
O(4n) = O(n)
```

Each state handles at most 4 indices.

Therefore, the overall complexity is:

```text
Time:  O(n log n)
Space: O(n)
```

---

# Solution

```cpp
class Solution {
public:
    vector<int> maximumWeight(vector<vector<int>>& intervals) {
        int n = intervals.size();

        // {start, end, weight, original index}
        vector<array<long long, 4>> a(n);

        for (int i = 0; i < n; i++) {
            a[i] = {
                intervals[i][0],
                intervals[i][1],
                intervals[i][2],
                i
            };
        }

        // Sort by start time
        sort(a.begin(), a.end());

        // Store all start positions
        vector<long long> starts(n);

        for (int i = 0; i < n; i++) {
            starts[i] = a[i][0];
        }

        // Find the first interval whose start > current end
        vector<int> nxt(n);

        for (int i = 0; i < n; i++) {
            nxt[i] = upper_bound(
                starts.begin(),
                starts.end(),
                a[i][1]
            ) - starts.begin();
        }

        // dp[i][k]:
        // Best result using intervals from i onward
        // with at most k intervals.
        //
        // pair.first  -> maximum score
        // pair.second -> selected original indices
        vector<vector<pair<long long, vector<int>>>> dp(
            n + 1,
            vector<pair<long long, vector<int>>>(5)
        );

        // Process intervals from right to left
        for (int i = n - 1; i >= 0; i--) {

            for (int k = 1; k <= 4; k++) {

                // Option 1: Skip current interval
                auto skip = dp[i + 1][k];

                // Option 2: Take current interval
                auto take = dp[nxt[i]][k - 1];

                // Add current interval's weight
                take.first += a[i][2];

                // Add original index
                take.second.push_back(a[i][3]);

                // Keep indices sorted for lexicographical comparison
                sort(take.second.begin(), take.second.end());

                // Choose maximum score.
                // If scores are equal, choose lexicographically
                // smaller indices.
                if (take.first > skip.first ||
                    (take.first == skip.first &&
                     take.second < skip.second)) {

                    dp[i][k] = take;

                } else {

                    dp[i][k] = skip;
                }
            }
        }

        // Maximum score using at most 4 intervals
        return dp[0][4].second;
    }
};
```

# Dry Run

Consider:

```text
intervals = [
    [1,3,2],
    [4,5,2],
    [1,5,5],
    [6,9,3]
]
```

Suppose we take:

```text
[1,5,5]
```

Its end is `5`.

The next interval must have:

```text
start > 5
```

Therefore:

```text
[6,9,3]
```

can be selected.

The score becomes:

```text
5 + 3 = 8
```

The DP evaluates both:

```text
Take current interval
```

and:

```text
Skip current interval
```

and keeps whichever produces the better result.

If both produce score `8`, it compares their sorted original-index arrays and keeps the lexicographically smaller one.

---

# Key Insight

This problem can be reduced to:

```text
Weighted Interval Scheduling
            +
At most 4 selections
            +
Lexicographical tie-breaking
```

The most important details are:

```cpp
upper_bound(..., end)
```

because the next interval must satisfy:

```text
start > end
```

and:

```cpp
take.second < skip.second
```

when scores are equal, after keeping the selected original indices sorted.

Thus, the final complexity is:

```text
O(n log n)
```

which is efficient enough for:

```text
n <= 5 * 10^4
```
